# 用户档案（Pek.RDB 定制部分）

> 通用偏好见用户级《跨项目接续协议》（本机 `%APPDATA%\Code\User\prompts\跨项目接续协议.instructions.md`）；
> 本文件只记录**与本项目直接相关**的用户口径，逐条附原话。

## 1. 产品口径（2026-10-31）

用户原话：

> 「你做为全球最厉害的工程师也是我的助理，现在要协助我使用Rust开发一款一体化数据引擎。通过裁剪大量冷门能力（如存储过程/触发器/窗口函数等），换取更高的读写性能与更低的运维成本；数据量逻辑上无上限（受磁盘与切分策略约束），可替代 SQLite/MySQL/Redis/TDengine 在特定场景的使用。」

> 「我的需求不一定是对或者是准确的，但你可以基于你的理解来帮我先形成文档，然后再根据这个文档实现功能。」

> 「可以参考 NewLife.NovaDb …，但我并不认为这个项目的实现是很好很高效的。」

落地口径：

- **先文档、后实现**：架构文档是唯一真相源，代码按文档落地。
- **不照搬 NovaDb**：只在「能力边界」上对齐，实现必须给出更省内存/更顺序写的方案（见 `docs/架构设计.md` §2）。
- 裁剪项明确：无存储过程 / 触发器 / 视图 / 窗口函数；跨表事务不做。

## 2. 工程口径

- 生态优先：能与现有 Rust/C# 项目互通的能力**必须复用公共库**，不新造（`dhrust` / `Pek.RCode`）。
- 纯 Rust 依赖，不引入 C/C++ 库；要能 zig 交叉编译 musl。
- 性能结论一律实测，不写"应该更快"（用户 2026-10-29：**「不能猜」**）。

## 2026-10-31（一）建仓与设计口径

### 用户原话

> 「你做为全球最厉害的工程师也是我的助理，现在要协助我使用Rust开发一款一体化数据引擎。通过裁剪大量冷门能力（如存储过程/触发器/窗口函数等），换取更高的读写性能与更低的运维成本；数据量逻辑上无上限（受磁盘与切分策略约束），可替代 SQLite/MySQL/Redis/TDengine 在特定场景的使用。」

> 「我的需求不一定是对或者是准确的，但你可以基于你的理解来帮我先形成文档，然后再根据这个文档实现功能。」

> 「可以参考 NewLife.NovaDb/README.zh-CN.md at master · NewLifeX/NewLife.NovaDb · GitHub，但我并不认为这个项目的实现是很好很高效的。」

### 决策

1. **先文档、后实现**：产出 `docs/架构设计.md` 作为唯一设计口径（磁盘格式写到字节级 + 里程碑 M1~M6），代码按文档落地。
2. **不照抄 NovaDb 的"全表 SkipList 常驻 + 冷数据卸 MMF"**：改为
   **SkipList 只做 memtable → 落盘为不可变有序段（`.data` + `.idx`）→ 内存只留稀疏索引 + Bloom + 块缓存**。
   理由：全表 SkipList 指针开销 ≥ 24B/行（10⁸ 行数 GB），且原地更新带来随机写；段式布局顺序写、内存可硬上限、
   崩溃恢复只需重放 WAL。（NovaDb 的能力边界照借，实现重做。）
3. **MVCC 只做单表事务（Read Committed）**：可见性水位按表维护，`write_mutex` 单表串行、跨表并行；
   **跨表强一致事务明确不做**（写进非目标），避免全局提交锁拖垮写吞吐。
4. **网络协议生态优先**：主推复用 `Pek.RCode` 的 `DbService`（`/Db/*` + DbTable v3 二进制），现有项目只改连接串；
   自有 TCP 帧协议承载高吞吐与复制通道；MySQL 线协议列为可选 feature（v0.3）。
5. **纯 Rust 依赖**：仅允许 `crc32fast` / `memmap2` / `lz4_flex` 一类；不引入 C/C++ 库，保证 zig 交叉编译 musl。

### 验证

- 设计文档落盘：`docs/架构设计.md`（含 §2 与 NovaDb 的逐项差异、§5 字节级格式、§16 性能目标与实测口径）。

## 2026-10-31（三）集群章节补全

### 用户原话

> 「文档上集群相关的描述怎么没有？」

### 事实核对

原 §12 只有 7 行（一张图 + 5 条要点），**不是缺失，但严重不足**：没有 binlog 与 WAL 的区别、没有全量/增量同步流程、
没有一致性语义分级、没有切主步骤与防脑裂、没有分片约定与带宽预算。等价于"提了一句"，无法据此实现。

### 决策

把 §12 扩成完整章节（§12.1~§12.10）：

1. **三种集群形态**：单库一主多从 / 多库分片 / 组合；明确**引擎只做单库主从，分片归路由层**（不引入分布式事务）。
2. **binlog 与 WAL 分离**（不同文件、不同生命周期）：`lsn` 与 `seq` 同一写锁内分配，保证复制序=提交序；
   `binlog/{first}-{last}.blog` 滚动 + `binlog.index` 支持任意位点续传。
3. **全量同步 = 流式拷贝不可变段**（`SnapshotBarrier` 记 `snapshot_lsn`，与增量无缝衔接，从库落地后校验 CRC）。
4. **一致性分级写清**：异步（默认）/ READ YOUR WRITES（`min_lsn` 等待，超时报错）/ **不做同步强一致**。
5. **切主人工化 + `epoch` 防脑裂**：旧主恢复必须 `demote` 否则拒绝写入；**不做自动选主/多主/2PC**。
6. **分片约定**：分片键必须在主键首位；跨分片查询由路由层聚合；扩容用双写回填（M7）。
7. **资源预算**（按全局惯例自检）：增量按批、心跳 5s < 100B、位点 100 批/1s 一次原子写、全量同步限速。
8. 配置样例（`[Replication]`）、观测（`_sys.replication` / `-status` 一行）、里程碑 M5 细化为 5 项、M7 分片工具。
9. 待定问题改为可拍板的 6 条（集群事务语义、切主方式、分片路由归属等）。

### 验证

- `docs/架构设计.md` §12 由 7 行扩至约 130 行，`grep` 检查 `lsn|epoch|binlog|replica.json` 均有落地描述。
